调度器对话框重复问题分析

🔴 问题描述

在调度器设置页面中，滚动下滑后会看到两个相同的运行历史组件，显示采集、处理、失败等相同信息。

📊 代码结构分析

SchedulerDialog (SchedulerDialog.tsx)
├── DialogContent (max-w-2xl max-h-[90vh] flex flex-col)
│   ├── DialogHeader
│   ├── ScrollArea (flex-1 overflow-y-auto)  ← 滚动容器
│   │   └── div (space-y-6 pb-6 min-h-0)
│   │       ├── 基本信息 section
│   │       ├── Separator
│   │       ├── 调度配置 section
│   │       ├── 错误提示
│   │       ├── Separator
│   │       └── 运行历史 section (第396-464行)  ← 唯一定义
│   └── DialogFooter (底部按钮)

🐛 根本原因

Radix UI ScrollArea 组件的内部结构问题

  • ScrollArea 使用了 ScrollAreaPrimitive.Viewport 来包裹子内容
  • 第17-19行：<ScrollAreaPrimitive.Viewport className="h-full w-full rounded-[inherit]">{children}</ScrollAreaPrimitive.Viewport>
  • 可能的原因1: ScrollArea 的 Viewport 内部渲染了两次 children
  • 可能的原因2: DialogContent 与 ScrollArea 的组合导致内容被克隆
  • 可能的原因3: CSS 的 flex 布局导致内容溢出并重复显示

✅ 解决方案

方案1: 移除 ScrollArea，使用原生滚动 (推荐)

<DialogContent className="max-w-2xl max-h-[90vh] flex flex-col">
  <DialogHeader />
  <div className="flex-1 overflow-y-auto px-6">  ← 直接使用 overflow-y-auto
    <!-- 内容 -->
  </div>
  <DialogFooter />
</DialogContent>

方案2: 修复 ScrollArea 的使用方式

<ScrollArea className="flex-1 px-6">
  <div className="space-y-6 py-6">  ← 移除 min-h-0
    <!-- 内容 -->
  </div>
</ScrollArea>

方案3: 检查是否有重复的组件调用

在 page.tsx 中检查是否同时导入了 SchedulerDialog 和 SchedulerDrawer

🔍 验证步骤

  1. 打开浏览器开发者工具
  2. 访问数据源页面，点击调度器设置按钮
  3. 在 Elements 面板中搜索 "运行历史" 文本
  4. 检查该文本出现的次数和DOM层级
  5. 查看是否有两个相同的 div.space-y-3 包含运行历史
