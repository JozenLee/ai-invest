## 🔄 数据更新机制详解

### 前端更新策略

```typescript
// MarketContext.tsx
- 初始加载: 页面打开时立即获取

  * 交易时段 (9:30-15:00): 每 30 秒刷新
```

## ⚠️ 发现的问题

### 问题: 收盘后数据更新可能延迟 5-10 分钟

**问题描述**:
- Python 服务的资金流向数据缓存时间为 **600 秒 (10 分钟)**
- 前端自动刷新间隔为 **300 秒 (5 分钟)**
- 导致收盘后 5-10 分钟内，用户可能看到盘中数据而非收盘数据

**影响范围**:
- 机构/散户资金流向
- 板块资金排名
- 北向资金净流入

**不受影响**:
- 指数价格 (缓存仅 30 秒)
- 市场状态判断 (实时计算)

**时间线示例** (假设 2026-07-29 收盘):

```
14:55 - 某用户访问，Python 缓存资金流向数据 (TTL=600秒，过期时间 15:05)
15:00 - 市场收盘
15:02 - AKShare/东方财富收盘数据处理完成
15:05 - 新用户访问:
        ├─ 前端请求 Next.js API
        ├─ Next.js 缓存未命中，请求 Python 服务
        ├─ Python 缓存刚好过期 (理论上会刷新)
        └─ 实际: 可能返回缓存或新数据 (取决于时间精度)
15:10 - 前端自动刷新:
        ├─ Next.js 缓存过期，请求 Python 服务
        ├─ Python 缓存已过期 5 分钟
        └─ ✅ 获取最新收盘数据
15:15 - 任何时候访问都能获取最新数据
```

## 🔧 优化建议

### 方案 1: 缩短资金流向缓存时间 (推荐)

**修改文件**: `data-service/providers/registry.py`

```python
# 第 73-92 行
"market_capital_flow": CategoryConfig(
    sources=["eastmoney_direct", "akshare", "sina"],
    cache_ttl=300,  # 从 600 改为 300
),
"sector_capital_flow": CategoryConfig(
    sources=["akshare", "sina", "tushare"],
    cache_ttl=300,  # 从 600 改为 300
),
"northbound_flow": CategoryConfig(
    sources=["eastmoney_direct", "akshare", "sina", "tushare"],
    cache_ttl=300,  # 从 600 改为 300
),
```

**优点**:
- ✅ 与前端刷新间隔一致
- ✅ 收盘后 5-10 分钟即可获取最新数据
- ✅ 减少数据不一致问题

**缺点**:
- ⚠️ API 调用频率增加 (10分钟/次 → 5分钟/次)
- ⚠️ 可能增加被限流风险
