# 知识图谱节点问题修复报告

## 📋 问题描述

**用户反馈**：知识图谱中有沪深300、科创50的节点，这跟其他节点的形式不同，且没有AI算力硬件。

## 🔍 问题分析

### 发现的问题

1. **通用指数节点问题**
   - 存在2个通用指数节点：沪深300、科创50
   - 类型为 `index`，与其他领域的 `xxx_index` 不一致
   - 这些是大盘指数，不属于特定领域

2. **AI算力硬件子图不完整**
   - 虽然有6个AI算力相关节点，但结构不完整
   - 节点类型：`chip_design`, `memory`, `server`, `cooling`, `optical_module`, `cpo`
   - 所有节点都是 Level 3，没有上层的指数和分类节点
   - 所有节点的 `parentId` 都是 `null`，没有层级关系

3. **与其他领域结构不一致**
   - 其他领域（如新能源汽车）有完整的三层结构：
     - Level 0: `nev_index`（指数）
     - Level 1: `nev_l1`（一级分类）
     - Level 2: `nev_l2`（二级细分）
   - AI算力硬件缺少这种结构

## ✅ 解决方案

### 1. 创建完整的AI算力硬件子图

执行脚本：`scripts/create-ai-compute-subgraph.ts`

**创建的节点结构**：

```
AI算力 (ai_index, Level 0)
├─ 芯片设计 (ai_l1, Level 1)
│  ├─ GPU/AI芯片 (ai_l2, Level 2)
│  └─ HBM高带宽内存 (ai_l2, Level 2)
├─ 算力基础设施 (ai_l1, Level 1)
│  ├─ AI服务器 (ai_l2, Level 2)
│  ├─ 液冷散热 (ai_l2, Level 2)
│  └─ 高性能存储 (ai_l2, Level 2)
└─ 网络互联 (ai_l1, Level 1)
   ├─ 800G光模块 (ai_l2, Level 2)
   └─ CPO共封装光学 (ai_l2, Level 2)
```

**创建的关系边**（5条）：
- GPU/AI芯片 → AI服务器（supply_chain）
- HBM高带宽内存 → GPU/AI芯片（supply_chain）
- AI服务器 → 液冷散热（demand_driver）
- AI服务器 → 800G光模块（demand_driver）
- 800G光模块 → CPO共封装光学（tech_evolution）

### 2. 清理通用指数节点

执行脚本：`scripts/cleanup-generic-indices.ts`

**删除的节点**：
- 沪深300（包括其2个子节点：信息技术、通信设备）
- 科创50

**理由**：
- 这些是大盘指数，不是特定领域的指数
- 每个领域应该有自己的专业指数（如AI算力对应中证人工智能）
- 保留会导致图谱结构混乱，与其他领域不一致

### 3. 添加市场数据元数据

执行脚本：`scripts/enhance-ai-compute-metadata.ts`

为所有AI算力节点添加元数据：
- **关联指数**：中证半导体（931865）、中证人工智能（930713）、中证通信设备（931160）
- **跟踪ETF**：半导体ETF（512480）、AI ETF（515070）、通信ETF（515880）
- **产业链位置**：upstream（上游）、midstream（中游）、supporting（支撑）
- **关键驱动因素**：AI训练需求、GPU供应紧张、数据中心建设等
- **关键玩家**：NVIDIA、华为、寒武纪、SK海力士等
