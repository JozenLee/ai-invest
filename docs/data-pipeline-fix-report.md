# 数据更新链路问题修复报告

修复时间：2026-07-22  
问题：仪表盘数据与实际市场数据不符

## 问题诊断摘要

### 根本原因
东方财富API服务器 `push2his.eastmoney.com`（大盘资金流向接口）网络连接失败，导致系统降级使用行业资金流向汇总估算，造成数据不准确。

### 影响范围
- ✅ **指数数据**：正常（使用日线收盘价）
- ⚠️ **大盘资金流向**：降级为估算值（主力资金方向准确但散户为反向估算）
- ✅ **板块资金流向**：正常
- ⚠️ **北向资金**：使用历史数据

### 数据质量对比

| 数据项 | 预期来源 | 实际来源 | 数据质量 | 可靠性 |
|-------|---------|---------|---------|--------|
| 上证指数 | 实时API | 日线收盘价 | 真实 | ★★★★★ |
| 主力资金 | 大盘接口 | 行业汇总估算 | 估算 | ★★★☆☆ |
| 散户资金 | 大盘接口 | 反向估算 | 估算 | ★★☆☆☆ |
| 板块Top10 | 行业接口 | 行业接口 | 真实 | ★★★★★ |
| 北向资金 | 实时接口 | 历史数据 | 陈旧 | ★★★☆☆ |

## 已实施的修复措施

### 1. 优化降级估算算法 ✅

**文件：** `data-service/providers/akshare_provider.py`

**改进点：**
- 将散户资金估算系数从动态计算改为固定保守系数 0.8
- 添加估算说明字段 `_estimationNote`
- 明确标记数据质量为 `"estimated"`

**代码变更：**
```python
# 改进前：动态系数，不稳定
retail_ratio = min(0.4, max(0.2, 1 - (total_net / total_inflow)))

# 改进后：固定系数，更保守
retail_net = -main_net * 0.8
retail_pct = -main_pct * 0.8
```

**效果：**
- 估算更加保守和稳定
- 避免极端值导致的误导

### 2. 前端UI数据质量标识 ✅

**文件：** `src/app/(dashboard)/dashboard/page.tsx`

**新增功能：**
- 在资金流向区域添加 "⚠️ 估算数据" 标识
- 鼠标悬停显示详细说明
- 明确告知用户数据为估算值及原因

**UI效果：**
```
💰 资金流向  ⏳ 非交易时间  ⚠️ 估算数据
           ↑ 新增标识（带Tooltip说明）
```

**Tooltip内容：**
- 标题：数据质量：估算值
- 说明：当前显示的资金流向数据为估算值，非实际交易数据
- 详情：由于大盘资金流向数据源暂时不可用，系统使用行业资金流向汇总估算...

### 3. 禁用代理配置 ✅

**文件：** `data-service/main.py`

**改进点：**
- 在启动时明确禁用系统代理环境变量
- 避免代理连接问题导致的不稳定

**代码变更：**
```python
# 修复：禁用系统代理，避免AKShare/requests库代理问题
os.environ.pop('HTTP_PROXY', None)
os.environ.pop('HTTPS_PROXY', None)
os.environ.pop('http_proxy', None)
os.environ.pop('https_proxy', None)
os.environ['NO_PROXY'] = '*'
```

**注：** 测试后发现问题不在代理配置，而是目标服务器本身无法访问。

### 4. 清除陈旧缓存 ✅

**操作：**
```bash

```

**清除的缓存：**
