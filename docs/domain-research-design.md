# 领域研究改造方案

## 目标与边界

以领域投资价值为研究对象，分别回答长期吸引力、20交易日时机、细分机会、产品表达与证伪条件。个人持仓不参与领域观点形成；研究观点不自动产生账户交易指令。

## 数据与流程

1. 复用冻结快照、来源日期、复权校验、企业财报和材料性事件。构造白名单证据包，保留缺失值与样本边界。
2. 新增 `domain-research` 节点，与原市场/事件/企业分析并行。只读取公开证据和计算指标，不读取 AI 摘要、历史观点、量化动作、账户或组合预算。保存输入哈希、完整输入、模型、提示版本和生成时间。
3. 模型输出领域吸引力、战术时机、因果链、反证、细分机会、产品映射及可观察的失效条件。逐项验证引用存在、产品范围、枚举和结构；失败保留错误，禁止用规则伪造 AI 结论。
4. 原分步综合分析继续生成基线。报告首先呈现独立领域研究，基线另行标记；交易权限和账户动作继续使用现有明确合同，领域观点不隐式覆盖账户仓位。
5. 归档比较：同快照但证据抽样/提示/模型不同的运行只算观察性比较，不能宣称严格 A/B 或收益优胜。记录双方输入、观点和限制；规则复核不得冒充新 AI 研究。

## 展示与兼容

报告首屏区分长期价值、战术时机、交易状态；展示主要依据、反证、细分机会和复核条件。旧报告缺少新字段时保留原展示。新增公开字段不包含个人持仓。工作流版本升级并显式声明端口。

## 验证与验收

- 单元：账户/历史观点/规则动作隔离；同证据哈希稳定；非法引用与越界产品拒绝；缺失不补零；输入预算超限显式失败。
- 集成：节点、DAG、归档及页面；规则复核不调用新模型；旧报告兼容。
- 真实快照：只读加载已完成运行的证据，执行新研究并保存独立实验 JSON，不改原报告与账户；明确历史快照上的事后研究可能受模型知识影响。
- 后续效果：必须在当时生成并归档的观点上做前向验证。领域方向预测与可交易策略收益分开；未形成明确仓位策略不计算策略收益。费用、下一可交易时点、基准和样本不足均需披露。

## 风险与发布

保留旧流程兼容与回退；新增领域观点失败不能显示成功。快照相同不代表输入完全相同，也不消除模型历史知识泄漏。开发闭环验证证明流程正确，不证明持续获利。待前向样本充足后才能决定是否移除原分步基线，避免提前丢失比较依据。

## 运行与验收入口

- `npm run analysis:verify-domain`：只读检查最新报告的冻结输入与预算。
- `npm run analysis:verify-domain -- --live`：调用配置的模型生成独立领域观点，成功和失败原文均保存到 `.runtime/domain-research/`，不写回原报告；可通过 `--report=报告ID` 固定样本。
- `npm run analysis:verify-domain -- --revalidate=实验JSON路径`：修复校验器后，校验输入哈希和版本，再验证已保存的原始模型响应；保留原失败记录并记录恢复时间，不改写模型结论。
- `DOMAIN_RESULT_PATH=/绝对路径/实验.json npm run analysis:verify-domain-ui`：在独立端口验证真实模型输出的桌面/移动展示及旧报告兼容，浏览器临时注入实验字段，不修改数据库。
- 新综合分析自动执行22节点流程；新报告保存领域观点、原分步基线对照及20交易日前向观察。规则复核仅标记未运行新领域研究。
- 前向观察按实际生成时间去重，跟踪首个声明产品相对基准的变化，不生成账户仓位或自动交易。严格同输入、同模型的多次随机盲测与扣费策略比较属于后续收益验收，不能用一次历史快照实验替代。
