# 市场数据刷新机制优化 - 变更总结

## 变更日期
2026-07-28

## 需求
- 交易时间1分钟刷新一次
- 非交易时间5分钟刷新一次
- 每次刷新同步更新：指数、资金流向、板块资金流向

## 修改文件

### 1. `src/contexts/MarketContext.tsx`
**变更**:
- 调整刷新间隔：交易时段 60秒（1分钟），非交易时段 300秒（5分钟）
- 新增板块资金流向同步更新
- 使用 `Promise.all` 并发请求三个API

**关键代码**:
```typescript
// 刷新间隔
const refreshInterval = marketMeta?.isOpen ? 60 * 1000 : 5 * 60 * 1000

// 并发请求
const [overviewRes, capitalRes, sectorRes] = await Promise.all([
  fetch(`/api/market/overview${refreshParam}`),
  fetch(`/api/market/capital-flow${refreshParam}`),
  fetch(`/api/market/sectors${refreshParam}`),
])
```

### 2. `src/app/api/market/overview/route.ts`
**变更**:
- 缓存TTL：交易时段 30秒 → 30秒（保持）
- 缓存TTL：非交易时段 30秒 → 120秒（增加）

### 3. `src/app/api/market/capital-flow/route.ts`
**变更**:
- 固定缓存 30秒 → 动态缓存（交易30秒，非交易120秒）
- 新增交易状态判断逻辑

### 4. `src/app/api/market/sectors/route.ts`
**变更**:
- 完全重写：从简单代理改为完整API实现
- 新增缓存机制（交易30秒，非交易120秒）
- 支持 `?refresh=true` 强制刷新参数
- 动态TTL根据交易状态调整

## 性能优势

### 1. 降低服务器负载
- 交易时段请求频率降低 83%（10秒 → 60秒）
- 非交易时段请求频率降低 80%（60秒 → 300秒）

### 2. 提升响应速度
- 使用并发请求，响应时间从累加变为取最大值
- 板块数据新增缓存，避免重复计算

### 3. 用户体验优化
- 交易时段1分钟刷新保证数据及时性
- 非交易时段5分钟刷新节省带宽
- 手动刷新支持强制更新
