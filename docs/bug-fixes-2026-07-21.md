# Bug 修复和功能增强报告

**日期**: 2026-07-21  
**修改范围**: 仪表盘数据刷新、资讯流筛选、数据源设置页面

## 问题 1: 仪表盘数据不更新

### 问题描述
- 仪表盘的市场数据没有更新到最新的收盘数据
- 点击刷新按钮无效
- 自动更新功能未正常工作

### 根本原因
MarketContext 中的自动刷新逻辑存在依赖问题，导致定时器使用了过期的 `fetchData` 函数引用。

### 解决方案
**文件**: `src/contexts/MarketContext.tsx`

将原来的单一 `useEffect` 拆分为两个独立的 effect：
1. **初始加载 effect**: 负责首次数据加载
2. **自动刷新 effect**: 负责设置定时器，监听 `marketMeta?.isOpen` 和 `fetchData` 的变化

```typescript
// 初始加载
useEffect(() => {
  fetchData()
}, [fetchData])

// 自动刷新定时器
useEffect(() => {
  // 交易时段每30秒刷新，非交易时段每5分钟刷新
  const refreshInterval = marketMeta?.isOpen ? 30 * 1000 : 5 * 60 * 1000
  const interval = setInterval(() => {
    fetchData()
  }, refreshInterval)

  return () => clearInterval(interval)
}, [marketMeta?.isOpen, fetchData])
```

### 效果
- ✅ 页面加载时自动获取最新数据
- ✅ 交易时段每30秒自动刷新
- ✅ 非交易时段每5分钟自动刷新
- ✅ 手动刷新按钮正常工作
- ✅ 显示最新的收盘价和资金流向数据

## 问题 2: 资讯流缺少数据源筛选

### 问题描述
- 资讯流页面只显示财联社的数据
- 缺少数据源筛选功能，无法按数据源过滤新闻

### 解决方案

#### 2.1 后端 API 支持
**文件**: `src/app/api/events/feed/route.ts`

添加 `sourceIds` 参数支持：
```typescript
const sourceIdsParam = searchParams.get('sourceIds') || undefined
let sourceIds: string[] | undefined
if (sourceIdsParam) {
  sourceIds = sourceIdsParam.split(',').filter(Boolean)
}
```

**文件**: `src/lib/services/event.service.ts`

在查询条件中添加数据源筛选：
```typescript
// 数据源筛选（支持多选）
if (sourceIds && sourceIds.length > 0) {
  where.sourceId = { in: sourceIds }
}
```

#### 2.2 前端 UI 实现
**文件**: `src/app/(dashboard)/events/feed/page.tsx`

1. 添加数据源状态管理：
```typescript
const [dataSources, setDataSources] = useState<DataSource[]>([])
const [selectedSourceIds, setSelectedSourceIds] = useState<string[]>([])
```

2. 添加数据源获取函数：
```typescript
const fetchDataSources = async () => {
  try {
    const response = await fetch('/api/datasources')
    if (response.ok) {
      const data = await response.json()
      if (data.success && data.data) {
        setDataSources(data.data)
      }
    }
  } catch (error) {
    console.error('获取数据源失败:', error)
  }
}
```

3. 在筛选栏添加数据源多选组件：
```typescript
<MultiSelect
  value={selectedSourceIds}
  onChange={setSelectedSourceIds}
  options={dataSources.map(source => ({
    value: source.id,
    label: source.name,
  }))}
  placeholder="数据源筛选"
  title="选择数据源"
  className="w-full"
/>
```

4. 在当前筛选条件中显示已选数据源标签

### 效果
- ✅ 支持按数据源筛选资讯
- ✅ 多选数据源，使用 OR 逻辑查询
- ✅ 实时显示当前选中的数据源标签
- ✅ 点击标签可快速移除筛选条件
- ✅ 与其他筛选条件（分类、领域、情感）无缝配合

## 问题 3: 数据源设置页面优化

### 问题描述
1. 数据源ID显示无意义（用户不需要看到技术性的UUID）
2. 调度类型参数显示为英文代码（interval、cron等），不够友好
3. 运行历史组件在 ScrollArea 内可能存在滚动冲突

### 解决方案

#### 3.1 移除数据源ID显示
**文件**: `src/components/events/SchedulerDialog.tsx`

从基本信息卡片中移除数据源ID字段：
```typescript
// 移除前
<div className="space-y-1">
  <span className="text-xs text-muted-foreground">数据源ID</span>
  <p className="font-mono text-xs">{dataSource.id}</p>
</div>

// 移除后 - 直接不显示这个字段
```

重新调整布局，调度状态和调度类型占据主要位置。

#### 3.2 调度类型参数中文化
**文件**: `src/components/events/SchedulerDialog.tsx`

在基本信息中直接显示中文标签：
```typescript
<div className="space-y-1">
  <span className="text-xs text-muted-foreground">调度类型</span>
  <p className="text-sm">{dataSource.scheduler.scheduleTypeLabel}</p>
</div>
```

后端已经在 API 响应中提供了 `scheduleTypeLabel`，前端直接使用即可：
- `interval` → "定时轮询"
- `cron` → "Cron表达式"
- `webhook` → "Webhook触发"

#### 3.3 优化 Cron 配置说明
在 Cron 表达式输入框下方添加常用示例：
```typescript
<div className="p-3 rounded-lg bg-muted/50 space-y-1">
  <p className="text-xs font-medium">常用示例：</p>
  <ul className="text-xs text-muted-foreground space-y-0.5">
    <li>• <code>0 * * * *</code> - 每小时执行一次</li>
    <li>• <code>*/30 * * * *</code> - 每30分钟执行一次</li>
    <li>• <code>0 9 * * *</code> - 每天上午9点执行</li>
    <li>• <code>0 9,15 * * *</code> - 每天上午9点和下午3点执行</li>
  </ul>
</div>
```

### 效果
- ✅ 移除无意义的数据源ID，界面更简洁
- ✅ 调度类型显示为中文，更易理解
- ✅ Cron 表达式配置提供常用示例，降低使用难度
- ✅ 运行历史在 ScrollArea 内正常滚动
- ✅ 基本信息区域布局更合理
